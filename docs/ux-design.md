## 1. 产品定位与设计原则

### 1.1 一句话定位

**Suna App 是 Suna Runtime 的跨设备掌控台：随时看到所有会话在做什么，随时接管任何一个。**

### 1.2 设计原则（决策时按此取舍）

| # | 原则 | 含义 |
|---|---|---|
| P1 | **掌控优先于速度** | Guard 决策、模型配置、审计记录必须完整可操作；宁可多一步确认，不隐藏安全语义 |
| P2 | **全局可见，任意接管** | 所有会话状态一眼可见（总览/侧栏），点击即 attach 接管；不锁死在单会话 |
| P3 | **静态优先，动态兜底** | 免费确定性信息（规则/状态/用量）常驻展示；LLM 类信息（review 结论）按需展开 |
| P4 | **Web 原生，不镜像 TUI** | 用鼠标/触控/键盘三态交互；移动端是决策终端不是缩小版桌面 |
| P5 | **状态三重表达** | 文字 + 图标 + 颜色；不只用颜色传达状态 |
| P6 | **移动优先** | 窄屏、触控目标 ≥44px、软键盘/IME、安全区、网络切换都要考虑 |
| P7 | **密度适中** | 桌面效率优先（信息密度高），移动端大目标优先 |
| **P8** | **用户友好，去术语化** | 用户不需要理解 Guard/MCP/cwd/protocol；所有界面用日常语言，技术概念折叠到"高级" |
| **P9** | **安全默认** | 局域网/公网访问必须有鉴权；默认仅本机可访问，开放需显式操作 + 明确提示 |

### 1.3 与 TUI 的边界

| 能力 | TUI | Web | 说明 |
|---|---|---|---|
| 模型/Provider 管理（增删改+API key） | ✅ 9 字段表单 | ✅ 表单化 | Web 表单更友好 |
| Guard 配置（模式/workspace/规则/审计） | ✅ | ✅ 设置中心 | Web 必做 |
| 附件（image_path/url） | ✅ 本地附件面板 | ✅ URL 列表 + 粘贴 | Web 无法读本地盘，URL 为主 |
| / 命令 | ✅ | ❌ 用 UI 元素替代 | Web 鼠标点选更快 |
| 窗口标题会话上下文 | ✅ | ✅ Header cwd 徽标 | 等价 |
| daemon 聚合状态面板 | ✅ full_status | ✅ daemon.status 轻量版 | Web 用轻量版 |
| 网络访问 | local socket | **HTTP(S) 局域网/公网** | Web 唯一优势，v2 核心 |

## 1A. 网络访问与安全（v2 新增）

### 1A.1 三种访问模式

| 模式 | 监听地址 | 鉴权 | 适用 |
|---|---|---|---|
| **本机**（默认） | `127.0.0.1` | 无（同机可信） | 桌面日常 |
| **局域网** | `0.0.0.0` 或指定网卡 | **Token 必须** | 手机同 WiFi 访问 |
| **公网（打洞）** | `0.0.0.0` + 打洞软件（tailscale/frp/cloudflared 等） | **Token + 可选 TLS** | 手机远程访问 |

### 1A.2 鉴权设计

```
启动时：
  首次启动生成随机 Token（32 字节 hex），写入配置（~/.suna-app/config.toml）
  控制台打印访问地址 + Token 二维码（终端）

浏览器访问：
  连接页输入：服务器地址 + Token（或扫二维码自动填入）
  登录成功后 Token 存 localStorage，所有请求带 Authorization: Bearer <token>
  SSE 事件流同样带 token（EventSource 无法带头，用 ?token= 查询参数或 cookie）

局域网免输入：
  手机与电脑同 WiFi 时，检测 mDNS（_suna-app._tcp）自动发现地址，仍须输 Token
```

### 1A.3 安全规则（强制）

1. **默认本机**：`--listen 0.0.0.0` 必须显式开启（flag + 配置文件双确认），开启时控制台醒目提示安全风险。
2. **监听非 loopback 时鉴权必开**：无 token 拒绝所有请求（401）。
3. **Token 校验**：`crypto/subtle.ConstantTimeCompare` 恒定时间比较，防时序攻击。
4. **传输安全**：公网打洞场景，打洞软件提供 TLS（tailscale 自带、cloudflared tunnel 自带 HTTPS）；本机/局域网 HTTP 明文可接受（Token 保护）。
5. **防暴力**：失败计数 + 指数退避（5 次失败锁 30 秒）。
6. **CORS/Origin**：仅允许配置的 origin 或同源访问；SSE 复用同源。
7. **不在日志记录 Token**；`/healthz` 不需要鉴权（健康检查），`/api/*` 全部需要。

### 1A.4 前端连接页（v2）

```
┌──────────────────────────────────────┐
│ 连接到 Suna                          │
│                                      │
│ 服务器地址（局域网/公网）              │
│ [ http://192.168.1.5:7633        ]   │
│                                      │
│ 访问令牌（首次连接时需要）             │
│ [ ••••••••••••••••          ]        │
│                                      │
│ [连接]   [扫码填入]                   │
│                                      │
│ 提示：本机访问无需令牌，地址填         │
│ localhost 即可                        │
└──────────────────────────────────────┘
```

- 本机场景：默认地址 `localhost:7633`，无 token 也能连（网关自动识别 loopback）。
- 移动端首次：扫码（电脑终端显示二维码）或手动输入。
- 记住连接（localStorage），下次免输入。

### 1A.5 对 Runtime 的影响

- Gateway 只负责 HTTP 层鉴权与转发；Runtime TCP 协议不动（仍 loopback 内部通信）。
- Runtime 的 workspace/Guard 边界不变；公网访问时**风险提示**（非 loopback 连接时 UI 顶部显示"远程连接"横幅，提醒操作谨慎）。

### 1A.6 远程模式的安全前置（v2 补全）

**现状约束**：`sameOriginUnsafe` 只认 loopback Origin（现有 CSRF 边界）；放开监听后必须适配：

| 风险 | 防护 |
|---|---|
| **CSRF**（恶意网页跨站调 API） | 本机模式保留现有 Origin 校验（loopback Host 匹配）；远程模式改 **Host + Token 双重校验**（请求必须带有效 Bearer Token，且 Host 头是预期地址） |
| **DNS rebinding**（恶意域名解析到 127.0.0.1） | 校验 `Host` 头在允许列表内（启动时确定的监听地址/主机名）；不匹配即 403 |
| **Token 泄漏** | 设置·连接可随时**重置 Token**（旧 Token 立即失效）；日志不记录 Token；前端 localStorage 存储（无 XSS 注入面，风险可控） |

## 1B. 分发与启动形态（v2 新增）

### 1B.1 核心结论

**用户双击即用，无 Terminal 窗口；gateway 为无窗口后台常驻进程，菜单栏/设置页可退出。**

### 1B.2 三平台分发形态

| 平台 | 形态 | 双击效果 | 无终端实现 |
|---|---|---|---|
| macOS | `Suna App.app`（zip 分发，拖入 Applications） | 双击图标即开 | 二进制入 `Contents/MacOS/` + Info.plist（`LSUIElement=true` 纯菜单栏 app，无 Dock 图标） |
| Windows | `.exe`（GUI subsystem） | 双击即开无黑框 | `-ldflags "-H=windowsgui"` + 托盘图标（systray，阶段 4 必做） |
| Linux | `.desktop` + 二进制 | 双击图标即开 | `.desktop` 的 `Exec` 不包终端；`xdg-open` 开浏览器 |

### 1B.3 启动流程

```
双击 App（或开机自启）
  → 单实例检查：已有实例？→ 复用（打开浏览器跳过去），不重复启动
  → 生成/读取 Token（首次生成，控制台打印地址+二维码）
  → 启动 HTTP server（本机或 0.0.0.0，依配置）
  → 拉起 Runtime daemon（懒启动，`suna serve --json`）
  → 打开浏览器 localhost（手动启动才弹；开机自启不弹）
  → 菜单栏图标常驻
```

### 1B.4 关闭机制（三层）

| 入口 | 说明 |
|---|---|
| **菜单栏/托盘图标**（主力） | 右键/点击 → 打开 / 开机自启开关 / 退出 |
| **设置页"退出"按钮** | `POST /api/v1/shutdown`（本机专属）→ 确认弹窗 → 优雅关闭 |
| **命令行** `suna-app stop` | 读 PID 文件发 SIGTERM（高级用户） |

**安全规则**：`/api/v1/shutdown` 仅允许 loopback 调用；手机远程访问时该端点返回 403（关闭必须由坐在电脑前的人操作）。

### 1B.5 优雅关闭流程

```
收到 SIGTERM / shutdown 请求
  → 有 run 在跑？→ 弹确认："任务仍在运行，退出后手机将无法查看，确定退出？"
  → HTTP server Shutdown（等存量请求完成）
  → 断开与 Runtime daemon 的 TCP 连接
  → 清理 PID 文件
  → 退出（无残留）

Runtime daemon 不受影响：
  gateway 退出 → daemon 继续跑完当前 run → 空闲 2s 自动退出（detached，已验证）
```

### 1B.6 边界处理（7 项）

| # | 边界 | 处理 |
|---|---|---|
| 1 | **日志与排障**（无终端后最重要） | 日志落盘 `~/.suna-app/logs/`；设置·连接"查看日志"入口；崩溃时显示可读错误（不是闪退无反应） |
| 2 | **二次启动** | 单实例锁（PID 文件 + 端口检测）；已有实例 → 打开浏览器复用，不报错 |
| 3 | **开机自启** | launchd（macOS）/ 启动项（Windows）；自启**不弹浏览器**，仅菜单栏图标；手动双击才弹 |
| 4 | **关闭时有 run 在跑** | 确认弹窗提示（见 1B.5），不无提示杀 |
| 5 | **运行中升级** | 新版 App 启动时检测旧实例 → 提示"已有旧版运行，请先退出"或自动接管（macOS 覆盖安装常见坑） |
| 6 | **无 GUI 环境**（SSH/headless） | 检测不到浏览器 → 只打印地址不弹；仍可正常服务（远程访问场景） |
| 7 | **强制关闭残留**（kill -9） | 下次启动清理残留 PID 文件；端口占用走现有回退逻辑 |
| 8 | **同机多账户** | 各自用户目录独立配置/Token；端口冲突走回退（7633→7634…） |

## 1C. PWA 与系统通知（v2 新增 · 移动端根基）

### 1C.1 现状

当前前端无 manifest / service worker / vite-plugin-pwa（public 为空，package.json 无依赖）。

### 1C.2 设计

| 项 | 说明 |
|---|---|
| **manifest** | 名称/图标/主题色/`display: standalone`（添加到主屏后全屏、无浏览器地址栏） |
| **Service Worker** | 离线壳（缓存 UI 静态资源，打开时秒开）；API 不缓存（SSE 实时） |
| **系统通知** | `Notification API`：收到 waiting 通知且页面不可见时发系统通知（"任务「修复登录页」等待你处理"）；点击通知 → 打开对应会话 |
| **权限时机** | 首次出现 waiting 且页面隐藏时请求通知权限（不提前打扰） |
| **安装引导** | 首次使用时提示"添加到主屏"（iOS Safari 需手动，Android Chrome 可自动提示） |

### 1C.3 与 §12.3 的关系

- §12.3 是**页内**体验（省电/弱网/锁屏恢复）；§1C 是**系统级**体验（安装/通知/离线壳）。
- 手机长时间使用 = 页内 + 系统通知两者都要：锁屏时靠系统通知叫醒用户，亮屏后靠页内状态恢复。

## 1D. 多连接与远程安全（v2 新增）

### 1D.1 多连接管理（远程场景核心）

用户可能连家里 Mac + 公司机器 + 云服务器：

```
连接页（v2）：
┌──────────────────────────────────────┐
│ 连接到 Suna                          │
│ ┌──────────────────────────────────┐ │
│ │ 我的 Mac（本机）        ● 已连接  │ │
│ │ 家里服务器              ○        │ │
│ │ 公司机器               ○        │ │
│ │ [+ 添加连接]                     │ │
│ └──────────────────────────────────┘ │
│ 添加连接：名称 + 地址 + 令牌（可扫码）  │
│ 记住选择（默认连上次的）              │
└──────────────────────────────────────┘
```

- 连接配置存 localStorage（多连接列表）；切换即重连。
- 本机连接（localhost）始终存在且免 token。

### 1D.2 远程风险告知（首次连接）

```
首次连接远程地址时弹窗：
┌──────────────────────────────────────┐
│ ⚠️ 远程连接确认                       │
│ 你将能通过此连接控制该电脑：           │
│ · 查看/执行任务、读写文件             │
│ · 处理安全确认（批准/拒绝）           │
│ 仅连接你信任的设备。                  │
│              [取消] [信任并连接]      │
└──────────────────────────────────────┘
```

### 1D.3 登出与 Token 失效

| 场景 | 处理 |
|---|---|
| 换设备/手机丢失 | 电脑端设置·连接**重置 Token** → 旧设备立即失效 |

## 2. 全局状态机（连接生命周期）

### 2.1 状态定义

```
disconnected ──initialize──▶ connecting ──成功──▶ connected
      ▲                        │                      │
      │                        ▼                      │ 断线
      └───────── 失败/断开 ◀── error ──重试─────▶ reconnecting
```

| 状态 | UI 表现 | 用户动作 |
|---|---|---|
| disconnected | 连接页（品牌卡片 + 连接按钮） | 点击连接 |
| connecting | 连接页按钮转"正在连接…" + 禁用 | 等待 |
| connected | 进入工作台 | — |
| error（runtime 不可用） | 连接页显示错误原因 + 重试 | 重试 / 查看日志 |
| error（协议不兼容） | 连接页**明确报错**"Runtime 协议版本过低/不支持"，不静默降级 | 升级 Runtime |
| reconnecting（运行中断线） | 不离开当前视图：顶部细条"连接已断开，正在重连…" | 等待；重连后自动恢复 |
| 重连成功 | 细条消失；会话以 Runtime 权威状态恢复（重新 attach） | — |

### 2.2 关键规则

- **断线不打断正在看的会话**：断线时保留当前聊天内容，只显示重连条；重连后自动重新 attach 当前会话并合并状态（现有 `useRuntimeSession` 语义保留）。
- **协议不兼容必须显式失败**：握手失败时展示具体原因（协议版本、缺 capability），引导升级 Runtime；禁止伪造状态。
- **Runtime 未 ready**：`runtime_unavailable` 错误（0.5 语义）显示"Runtime 正在启动"，带重试按钮；`retryable=true` 时自动重试一次。

### 7.2 执行流渲染（核心改造：工具行紧凑化）

**现状问题**：工具是"大卡片"（圆角边框 + 整块），一屏只能看 3-4 个，视觉重。

**目标形态**：

```
┌──────────────────────────────────────────────┐
│ 思考（ReasoningBlock，现有）                    │
│ ──────────────────────────────────────────── │
│ ⟳ EditFile  src/lib/foo.ts            1.2s ✓ │   ← 工具行（折叠态）
│ ⟳ Exec  pnpm test                     8.4s ✗ │   ← 失败红色
│ ⟳ Skill  img  [已加载]                       │   ← 技能行
│ ──────────────────────────────────────────── │
│ 回复（assistant 消息，现有）                    │
└──────────────────────────────────────────────┘
```

**工具行规格**：
- 单行：状态图标（⟳ 运行中动画 / ✓ 成功 / ✗ 失败 / ⚠ guard）+ 工具名 + 目标摘要（path/command，截断）+ 耗时 + 状态色点。
- **点击展开**：展开显示参数（脱敏后）与结果（现有 ToolCard 内容），可折叠。
- 连续同工具合并显示"×N"（如 `⟳ Exec ×3`），展开后按次展示。
- 保留现有上限（24 卡/run）与回合清空语义，仅改视觉形态。
- 新增字段：**工具耗时**（前端本地计时：tool_start→tool_end，现有协议无 duration 字段，前端计算）。

**技能行**：同形态，一行 `📖 技能 img [已加载]`，review 结论点击展开（现有 SkillCard 改行化）。

### 7.3 Subtask 组（对齐 TUI 但 Web 化）

```
┌──────────────────────────────────────────────┐
│ ▸ 🤖 子任务：分析日志 (spawn)     3 个工具 运行中 │   ← 折叠行
│   ├ ⟳ ReadFile  logs/app.log         0.3s ✓ │   ← 展开后内嵌工具行
│   ├ ⟳ Exec  grep error               1.1s ✓ │
│   └ ⟳ Search  "panic"                0.8s ✓ │
└──────────────────────────────────────────────┘
```

- **实现**：前端追踪 `spawn` 工具的生命周期——`tool_start(spawn)` 创建组；spawn 返回后到该 spawn 结果之间到达的其它工具调用归入该组（按时间窗 + 工具归属推断，协议无父子字段，用"spawn 执行期间产生的工具"分组，spawn 结束即组结束）。
- **局限说明**：协议无显式子任务边界，此为近似分组；真实子任务结果在 `tool_end(spawn)` 的 result 中，组内工具为期间全局流。若后续协议加 subtask 事件再精确化。
- 折叠默认收起，展开看组内工具。

### 7.4 确认 / 提问决策卡（增强 modify · 用户友好化）

**现状**：只显示 reason + 批准/拒绝。

**目标**（guard 有 suggestion 时）：

```
┌──────────────────────────────────────────────┐
│ ⚠️ 需要确认 · 执行命令                        │
│ rm -rf dist                                  │
│ 原因：删除目录，不可逆                         │
│ 建议改为：rm -rf dist/tmp                     │   ← suggestion 展示
│                                              │
│ [✓ 按建议执行] [拒绝] [批准原操作]              │   ← modify 一键
└──────────────────────────────────────────────┘
```

- 三按钮只在 `suggestion` 存在且 `can_reply` 时显示；无 suggestion 时保持两按钮（批准/拒绝）。
- 决策卡**只在时间线内嵌一处**；右栏只显示"等待你确认/回答"状态条（不重复按钮）。
- 只读场景（`can_reply=false`，其他客户端处理中）显示"由其他设备处理"。

### 7.5 Composer

- 现状保留：textarea 无边框 + 外卡片 focus 光晕 + 发送按钮品牌渐变 + 图片 URL input。
- 增强：**多图 URL 列表**（chip 形式，可删除）；**粘贴图片**时提示"请提供 URL（Web 无法读取本地文件）"。
- observer 状态：输入区虚线置灰 + "当前为观察者"提示（现有）。
- waiting 状态：发送按钮禁用 + 提示"等待你回复其他会话的请求"。

### 7.6 附件能力边界（2026-08 确认）

对外协议 `AttachmentRef.Kind` 只接受三种：`path` / `url` / `attachment`，明确拒绝 base64/blob。
对第三方 UI 的实际可用性：

| kind | TUI | Web | 说明 |
|---|---|---|---|
| `url` | ✅ | ✅ 唯一可用 | 当前多图 chips 已实现 |
| `path` | ✅ 拖拽/粘贴生成临时文件 | ❌ 浏览器拿不到本地绝对路径 | Web 需 gateway 桥接（见下） |
| `attachment` | ✅ 附件面板 | ❌ 不可达 | `attachment.*` 方法明确不对第三方开放，无法生成/引用 |

**待议增强：gateway 本地图片上传桥接（转 path）**

```
浏览器 multipart POST → gateway 落盘临时文件 → 以 path kind 发给 runtime
```

- runtime 与 gateway 同机，`path` 指向 gateway 写的本地文件即可被 runtime 直接读取
  （等价于 TUI 拖拽图片的做法：生成临时文件 → path kind），**无需触碰 attachment**
- 需定：存储位置、生命周期/清理、大小限制、鉴权（是否限本机）
- 状态：**暂缓**，待有真实本地图片上传需求时再实施

## 11. 多会话通知机制

### 11.1 场景

用户正在工作台看 A 会话，B 会话（另一客户端/另一运行）进入 waiting。

### 11.2 设计（三层递进）

1. **侧栏徽标**：B 会话行 amber 状态点 + 组名琥珀点 + "需要你处理"计数（总览入口）。
2. **工作台顶部通知条**（当 A 会话在 viewing 时）：
   ```
   ┌──────────────────────────────────────────────┐
   │ 🔔 会话「修复登录页」正在等待你处理    [切换] [忽略] │
   └──────────────────────────────────────────────┘
   ```
   - 点击切换 → attach B；忽略 → 5 分钟后或下次 waiting 变化再提示。
   - 同屏最多一条（按最新）。
3. **文档标题徽标**：`(1) Suna App`——waiting 数，桌面任务栏可见。

### 11.3 规则

- 通知条只在"当前选中会话 ≠ 待处理会话"时出现。
- 自己正在查看的会话 waiting → 走现有决策卡，不弹通知条。
- 移动端：通知条 + 总览徽标，无桌面任务栏。

## 17. 设计决策记录（ADR）

| 决策 | 理由 |
|---|---|
| 工具卡片→行 | 行业共识（Claude Code/OpenHands/Devin），密度与扫读效率 |
| 决策卡只留时间线 | 双处重复分散注意力；右栏降级为状态条 |
| cwd 必选但零输入 | 协议必传 cwd；默认最近 + 列表点选消除输入负担 |
| 审计 UI 暂不做 | 协议无 method；先展示配置，审计等协议增强 |
| Subtask 近似分组 | 协议无边界事件；用 spawn 时间窗近似，注明局限 |
| 移动端默认总览 | 决策终端定位，快速接管优先 |
| 设置中心用覆盖层 | 不打断会话浏览；六 Tab 分组清晰 |
| **去术语化（v2）** | 用户不关心 Guard/MCP/cwd；日常语言 + 高级折叠，功能完整但界面简单 |
| **远程访问必须鉴权（v2）** | 公网/局域网暴露控制台 = 暴露本机文件操作能力；无鉴权即高危，Token 强制 |
| **默认仅本机（v2）** | 非 loopback 需显式开启（flag+配置双确认），防误暴露 |
| **移动端长时间使用（v2）** | 省电（无轮询/隐藏暂停）、弱网重连、锁屏恢复、单手操作；手机是核心客户端 |
| **无窗口后台常驻（v2）** | 双击即用无 Terminal；菜单栏退出 + 设置页退出 + 命令行 stop 三层入口；daemon 解耦不受影响 |
| **远程不能关（v2）** | shutdown 端点 loopback-only，避免手机误触断掉远程入口 |
| **日志落盘（v2）** | 无终端后日志必须可查（~/.suna-app/logs/ + 设置页入口），崩溃可读 |
| **PWA 是移动端根基（v2）** | 无 manifest/SW 则手机无法"添加到主屏"、无法系统通知；阶段 0.5 必做 |
| **多连接支持（v2）** | 用户可能连多台机器（家/公司/云）；连接配置列表化 |
| **远程首次信任弹窗（v2）** | 远程=控制本机文件，必须显式知情同意 |
| **localStorage 版本化（v2）** | 结构演进不静默错乱；命名空间 + schema 版本 + 迁移 |
